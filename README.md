# Mosgortrans appeals MVP

Сквозной сценарий: загрузка файла → OCR/извлечение текста → гибридный RAG (Qdrant + LlamaIndex) → черновик ответа (Qwen2.5 через vLLM или любой OpenAI-совместимый сервер, например Ollama) → правка → экспорт DOCX.

## Состав

- `backend/` — FastAPI, адаптеры OCR / RAG / LLM, конвейер, экспорт DOCX
- `frontend/` — раздельный экран исходного документа и редактора ответа (nginx)
- `data/knowledge_base/` — стартовые материалы для индексации

Авторизация, СЭД и аналитика в MVP не входят.

## Быстрый старт

1. Скопируйте `.env.example` в `.env`.
2. Выберите режим работы (см. ниже).
3. Соберите и запустите стек: `docker compose up --build`
4. Дождитесь в логах бэкенда строки `Application startup complete` (см. «Время запуска»).
5. Откройте http://localhost:3000

> **Windows и кириллица в пути.** Если в названии папки проекта есть кириллица, Docker Compose выдаст ошибку `project name must not be empty`. Задайте имя проекта вручную:
> `docker compose -p transport up --build`
> или добавьте в `.env` строку `COMPOSE_PROJECT_NAME=transport` (тогда ключ `-p` не нужен). Ниже в командах `-p transport` опущен.

Остановка: `docker compose down`. Запуск в фоне: `docker compose up -d`. Логи: `docker compose logs -f backend`.

> После изменения `.env` выполните `docker compose up -d`: контейнер пересоздастся и перечитает настройки. Команда `restart` файл `.env` не перечитывает. Правки в коде требуют пересборки: `docker compose up --build -d`.

## Режимы работы

Каждый компонент переключается переменной в `.env`:

| Переменная | Значения | Что делает |
|---|---|---|
| `OCR_PROVIDER` | `paddle` / `stub` | распознавание сканов и изображений |
| `LLM_PROVIDER` | `vllm` / `stub` | генерация черновика ответа |
| `RAG_PROVIDER` | `llamaindex` / `stub` | поиск по базе знаний |

### Демо без GPU (заглушки)

```
OCR_PROVIDER=stub
LLM_PROVIDER=stub
RAG_PROVIDER=stub
```

Заглушки нужны только для проверки интерфейса и конвейера, это не рабочий режим:

- `OCR_PROVIDER=stub` не распознаёт сканы. Читаются только PDF с текстовым слоем, `.txt` и `.docx`. Для скана PDF или изображения в результат попадает пометка `[stub-ocr]`.
- `LLM_PROVIDER=stub` не обращается к модели. Черновик собирается из фиксированного шаблона с вставкой распознанного текста и фрагментов базы знаний (в шаблоне есть пометка о резервном режиме).
- `RAG_PROVIDER=stub` использует простой поиск по ключевым словам без Qdrant и эмбеддингов.

### Рабочий режим

```
OCR_PROVIDER=paddle
INSTALL_OCR=1
LLM_PROVIDER=vllm
RAG_PROVIDER=llamaindex
```

## Настоящая языковая модель

Адаптер `vllm` отправляет запросы в формате OpenAI на `VLLM_BASE_URL/chat/completions`. Любое значение `LLM_PROVIDER`, кроме `stub`, включает этот адаптер. Подойдёт vLLM, Ollama, LM Studio и другие OpenAI-совместимые серверы.

### Вариант 1: vLLM (по умолчанию)

Qwen2.5-14B-Instruct должна быть доступна по `VLLM_BASE_URL` (OpenAI-compatible `/v1`). Для такой модели нужна мощная видеокарта NVIDIA, на Windows vLLM обычно запускают через WSL2 или на отдельном сервере.

### Вариант 2: Ollama (проще для локального запуска, в том числе на Windows)

1. Установите Ollama с https://ollama.com и убедитесь, что он запущен: `ollama list`.
2. Скачайте модель: `ollama pull qwen2.5:7b`. На слабом компьютере или без видеокарты NVIDIA берите `qwen2.5:3b`: она быстрее, но отвечает хуже.
3. Укажите в `.env`:
   ```
   LLM_PROVIDER=vllm
   VLLM_BASE_URL=http://host.docker.internal:11434/v1
   VLLM_MODEL=qwen2.5:7b
   LLM_TIMEOUT_SECONDS=180
   ```
   Значение `VLLM_MODEL` должно совпадать с именем из `ollama list`.
4. Примените настройки: `docker compose up -d`.

Проверка связи из контейнера:

```
docker compose exec backend python -c "import httpx; print(httpx.get('http://host.docker.internal:11434/api/tags', timeout=10).text)"
```

Если запрос завершается ошибкой подключения, Ollama слушает только `127.0.0.1`. Задайте системную переменную Windows `OLLAMA_HOST=0.0.0.0`, полностью перезапустите Ollama и при необходимости разрешите порт 11434 в брандмауэре.

Первый запрос после запуска модели выполняется дольше обычного: она загружается в память. На компьютере без видеокарты генерация может занимать минуты, поэтому таймаут LLM стоит увеличить.

## OCR (PaddleOCR)

Для включения: `INSTALL_OCR=1` и `OCR_PROVIDER=paddle`, затем пересборка образа (`docker compose up --build`).

- При **первом** распознавании PaddleOCR скачивает модели (детекция, кириллическое распознавание, классификатор). Они сохраняются внутри контейнера в `/root/.paddleocr` и пропадают при его пересоздании. Первый запрос может не уложиться в таймаут и завершиться ошибкой `ocr_timeout`. Увеличьте `OCR_TIMEOUT_SECONDS` и повторите загрузку после того, как модели скачаются. Чтобы они не скачивались заново, можно примонтировать том к `/root/.paddleocr` в `docker-compose.yml`.
- Цифровые PDF (с текстовым слоем) читаются без OCR. Распознавание применяется к сканам и изображениям.
- Качество на сложных документах (фон с защитными узорами, печати, мелкие поля, низкое разрешение) заметно хуже, чем на чистых машинописных текстах. Для проверки используйте обычное напечатанное обращение.

## Настройки таймаутов

Таймауты задаются в `.env` (значения по умолчанию указаны в скобках):

- `OCR_TIMEOUT_SECONDS` (30)
- `LLM_TIMEOUT_SECONDS` (45)
- `RAG_TIMEOUT_SECONDS` (20)

Если генерация срывается, интерфейс получает распознанный текст и сообщение об ошибке.

> Тексты ошибок о таймаутах в коде содержат фиксированные «30 сек» и «45 сек». Реальное значение берётся из `.env`, поэтому сообщение при изменённых настройках может не совпадать с ним.

## Время запуска

- Первая сборка образа занимает порядка 7–10 минут (тяжёлые библиотеки: torch, эмбеддинги, PaddleOCR).
- После старта бэкенд может подниматься до нескольких минут (загрузка библиотек и индексация базы знаний).
- Пока в логах бэкенда нет `Application startup complete`, nginx отвечает `502 Bad Gateway`, а интерфейс показывает ошибку вида `Unexpected token '<' ... is not valid JSON` (вместо JSON приходит HTML-страница ошибки). Это не сбой: подождите и повторите.

## Адреса и порты

| Что | Адрес |
|---|---|
| Интерфейс | http://localhost:3000 |
| API (через nginx) | http://localhost:3000/api/v1/... |
| Проверка состояния | http://localhost:3000/api/v1/health |
| Бэкенд (внутри сети Docker) | `backend:8080` |
| Qdrant | порт 6333 (web UI: `/dashboard`) |

`/api/v1/health` возвращает активные провайдеры (`ocr_provider`, `llm_provider`, `rag_provider`), это самый быстрый способ проверить, что настройки из `.env` применились.

## API

- `GET /api/v1/health`
- `POST /api/v1/process-document` — multipart `file`
- `POST /api/v1/export-docx` — JSON `{ "answer_text", "request_id?" }`

Допустимые форматы: `.pdf`, `.jpg`, `.jpeg`, `.png`, `.txt`, `.docx`. Максимальный размер файла: 20 МБ.

## Частые проблемы

| Симптом | Причина и решение |
|---|---|
| `project name must not be empty` | В имени папки кириллица. Используйте `docker compose -p transport ...` или `COMPOSE_PROJECT_NAME=transport` в `.env`. |
| `502 Bad Gateway`, ошибка про `<html>` вместо JSON | Бэкенд ещё запускается. Дождитесь `Application startup complete` в логах бэкенда. |
| `ocr_timeout` (422), `Превышено время ожидания OCR` | PaddleOCR скачивает модели или документ тяжёлый. Увеличьте `OCR_TIMEOUT_SECONDS`, повторите запрос. |
| В тексте обращения мусор из букв | Низкое качество скана или сложный фон. Используйте скан лучшего качества или напечатанный документ. |
| «локальная LLM недоступна» в черновике | В `.env` выбран `LLM_PROVIDER=stub`. Подключите настоящую модель (см. выше). |
| `Генерация ответа моделью недоступна ... All connection attempts failed` | Сервер модели недоступен по `VLLM_BASE_URL`: не запущен Ollama/vLLM, неверный порт или Ollama слушает только `127.0.0.1` (см. `OLLAMA_HOST`). |
| `rag_index_fallback ... llama-index-readers-file package not found` | Индексация базы знаний откатилась на упрощённый поиск. Добавьте пакет `llama-index-readers-file` в `backend/requirements.txt` и пересоберите образ. |
| Изменения в `.env` не применились | Выполните `docker compose up -d` (не `restart`). |

## Безопасность данных

Для проверок используйте обезличенные образцы обращений. Не загружайте реальные документы граждан (свидетельства, паспорта и т. п.) в тестовую среду.
